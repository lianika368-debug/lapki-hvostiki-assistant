# Лапки & Хвостики — ассистент

**Учебный кейс:** пример работы AI-ассистента, без реальной записи в салон. Используйте только вымышленные данные. Подтверждённые тестовые заявки действительно сохраняются в Supabase и отправляются в Telegram. Плашка «Демо · учебный кейс» размещена в шапке, предупреждение о тестовых заявках — под полем ввода, перед кнопкой «Подготовить заявку», и остаётся видимым во время разговора.

Gradio 6.30.0, Python 3.12, Google Gemini (`google-genai`), Supabase и Telegram.
Ассистент консультирует без контактов и по желанию готовит предварительный запрос администратору.
Сведения о салоне — только из `salon.json`. Доступа к расписанию нет.

## Промпт Лапки и блок ДАННЫЕ

Пользовательский промпт хранится в `lapka_prompt.txt`. В свободном диалоге Gemini сначала
возвращает структуру намерения и фактов (`gemini_client.py`), затем оформляет выбранный
сервером ответ в стиле Лапки (`lapka.py`). Используется тот же `GEMINI_API_KEY` и `GEMINI_MODEL`.

Второй запрос содержит JSON-блок `ДАННЫЕ`: релевантные сведения и цены из `salon.json`,
ответ приложения, статус заявки, недостающие обязательные поля и следующий вопрос.
В контекст оформления не добавляются имя и телефон из черновика; история последних 10 сообщений
может содержать сообщённые клиентом данные. Для разбора сообщения сохраняется история последних 40 сообщений.
При консультации приложение не даёт команды собирать контакты, даже если черновик ещё не заполнен.

Python проверяет новые числа, неизменность строк прайса с «от», неподтверждённые обещания,
количество вопросов и длину ответа. При ошибке Gemini/JSON или отклонённом тексте показывается
исходный ответ приложения; черновик не теряется. Это дополнительная консервативная проверка,
а не универсальное доказательство достоверности любого текста модели.

Медицинские вопросы, попытки подменить правила, сообщения вне темы, проверка полей,
подтверждение, сохранение и повторная отправка обрабатываются сервером.
Сводка, полный прайс и быстрые справочные ответы показываются из проверенных шаблонов,
поэтому могут быть длиннее 2–4 предложений. Модель оформления не вызывает базу или Telegram.

## Локальный запуск

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock
cp .env.example .env
# Заполните .env своими ключами; не публикуйте его.
python app.py
```

Откройте http://localhost:7860. `PORT` меняет порт. Для тестов установите `requirements-dev.txt`.

| Переменная | Назначение |
| --- | --- |
| `GEMINI_API_KEY` | Ключ Google AI Studio, только сервер |
| `GEMINI_MODEL` | По умолчанию `gemini-3.5-flash-lite` |
| `SUPABASE_URL` | URL проекта Supabase |
| `SUPABASE_SERVICE_ROLE_KEY` | Серверный ключ, не anon/publishable |
| `TELEGRAM_BOT_TOKEN` | Токен бота из @BotFather |
| `TELEGRAM_CHAT_ID` | Чат администратора, предварительно запустившего бота |
| `GRADIO_ANALYTICS_ENABLED` | `False` |

## Диалог и минимальная заявка

Для консультации контакты не нужны. Для передачи необходимы **телефон и выбранная услуга либо описание задачи**.
Имя, кличка, порода, возраст, вес, точные дата/время, мастер и комментарий не запрашиваются автоматически.
Отсутствующие значения — `NULL`, а не вымышленные имена или предпочтения.
Уточнение зависит от задачи. Неизвестную категорию размера/услугу можно передать администратору для согласования.

Размер собаки нельзя определять по породе или килограммам: салон не предоставил границы.
Один справочник и серверное правило выбирают категорию для цены и заявки. Длительность неизвестна.
Рекомендация отделена от выбора клиента. Указанные даты и время — пожелания, не бронь.
В одном черновике один питомец; при явном переключении старые параметры питомца очищаются.

Сводка показывает только известные факты, ориентировочную цену, обсуждённые темы и нерешённые вопросы.
Отправка выполняется только по точному подтверждению и только для текущей версии сводки.
Неверное исправление сохраняет старое значение, но блокирует отправку до исправления или явного отказа от изменения.

## База и миграция

Для нового проекта выполните `supabase/create_applications.sql`, затем
`supabase/migrations/20261025090000_adaptive_applications.sql`.
Для существующей таблицы — только второй файл. Он не удаляет записи, делает дополнительные сведения
необязательными и добавляет `pet_type`, `pet_weight`, `pet_size`, `request_text`, `schedule_note`, `handoff`.
Старые записи совместимы. Новые должны содержать услугу или суть запроса; телефон остаётся обязательным.

RLS включён. `anon`, `authenticated`, `public` не получают доступа; серверу нужны только INSERT и SELECT.
Запустите `supabase/verify_security.sql`: все значения должны быть `true`.
Миграция подготовлена обычным SQL для существующего проекта; CLI в рабочем окружении отсутствовал,
попытка запуска через реестр завершилась сетевым таймаутом. Применение через SQL Editor проверено отдельно.

## Сохранение и Telegram

Сначала сервер вставляет заявку с UUID, затем читает её номер и проверяет результат.
Только после этого отправляет компактные данные и резюме в Telegram.
`sendMessage` проверяет HTTP-статус, `ok` и номер сообщения. HTML/Markdown не включаются.
Длинный Unicode-текст разбивается на части в пределах ограничения Telegram.

После ошибки базы UUID и черновик сохраняются для повторной попытки; повторная вставка не создаёт дубль.
При ошибке Telegram заявка остаётся в базе. Серверный лог содержит безопасный номер заявки,
а не токен, телефон или исходный ответ API. Очереди гарантированной доставки/автоповторов Telegram нет.
При отключённых обеих Telegram-переменных уведомления не отправляются.

## Интерфейс, память и границы

История и черновик — отдельные `gr.State` на сервере, TTL 1 час. В браузере персональные данные
постоянно не сохраняются. Обновление страницы, закрытие вкладки или перезапуск сервиса могут потерять черновик.
Перезагрузка сама не отправляет заявку заново. Восстановление черновика/UUID после потери сессии не реализовано;
повторно заполненная и подтверждённая новая сессия считается новой заявкой.

Одна кнопка «Начать заново» требует подтверждения; сбрасывает историю, исправления и версию сводки.
Уже переданную заявку очистка не удаляет. Enter отправляет, Shift+Enter переносит строку.
На мобильном поле закреплено внизу; высота переписки адаптивна. Названия стандартных элементов переведены
через I18n и небольшой DOM-адаптер для жёстко заданных строк Gradio 6.30.

Чат — обычный текст с очисткой HTML; сводка экранируется. API-ключи остаются на сервере.
Подтверждение проверяется в Python, включая вызов обработчиков напрямую.
Ограничение сообщения 4 000 символов, очередь 32, последовательная обработка и интервал 1 секунда.
Для большого трафика нужен внешний лимит запросов. Это сервис с одной репликой, без долговременного хранения сессий.

## Проверки

```bash
python -m pytest -q
# Отдельный добровольный тест настоящего Gemini на синтетических данных.
# База и Telegram в нём подменены; он не создаёт реальных заявок.
RUN_GEMINI_SMOKE=1 python smoke_scenarios.py
# Пять каверзных сообщений с настоящим разбором и оформлением Gemini.
# Сохранение и Telegram здесь также подменены.
RUN_LAPKA_SMOKE=1 python check_lapka.py
```

`tests/test_supabase_failure.py` — отдельная проверка недоступности базы, сохранности черновика и отсутствия Telegram.
`tests/test_adaptive_conversation.py` — адаптивные сценарии, исправления, цена, время, отказы и подтверждение.
`tests/test_handoff_flow.py` — весь серверный путь через подменённые HTTP-ответы, включая Telegram 401.
`tests/test_ui_summary.py` — дата на русском, неполные пожелания по времени и безопасное отображение полей сводки.
`tests/test_lapka.py` — блок ДАННЫЕ, отклонение выдуманных цен/обещаний, ошибки модели и сохранность отправки.
`reports/lapka-smoke.json` — результаты пяти запросов к настоящему Gemini на вымышленных данных.
`reports/verification.md` — наблюдения до/после, число уточнений, результаты и непроверенные границы.
`reports/gemini-smoke.json` содержит только синтетические сообщения, используемые при проверке.

## Render

Сохраняется существующий Web Service, Python 3.12.15:

- Build: `pip install -r requirements.lock`
- Start: `python app.py`
- Health check: `/healthz` (проверяет процесс, а не внешние API)
- Ключи: Render → Environment; `PORT` назначает Render.
- Бесплатный тариф может засыпать: после простоя возможен холодный старт.

Перед выкладкой кода примените расширение таблицы. Затем отправьте commit в GitHub;
автодеплой из `main` включён. `.env` и секреты в репозиторий не включаются.
