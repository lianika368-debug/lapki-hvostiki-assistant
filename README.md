# 🐾 Лапки & Хвостики — AI-ассистент

Веб-чат груминг-салона на Python 3.12, Gradio, официальном `google-genai` и Supabase. Без агентских фреймворков.

## Возможности

- Намерения: **цена**, **запись**, **общее**; медицинские вопросы направляются к ветеринару.
- Gemini извлекает типизированные данные, а Python выбирает ответы из `salon.json`. Модель не генерирует цены, свободные слоты и правила.
- Отдельные серверные `gr.State` для истории и черновика каждой сессии. Уже известные поля не спрашиваются заново.
- Пошаговый сбор заявки, итог, явное подтверждение, сохранение в Supabase. Правки требуют повторного подтверждения.
- Повтор после сетевого таймаута использует тот же UUID и не создаёт дубликат.
- Заявка означает желаемое время: приложение не имеет календаря свободных мест и не подтверждает запись.

## Локальный запуск

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.lock
cp .env.example .env
# Заполните .env своими ключами, не отправляйте его в GitHub.
python app.py
```

Откройте http://localhost:7860. Требуется Python 3.11+, рекомендуется 3.12. Порт задаётся `PORT`.

Переменные:

| Переменная | Назначение |
| --- | --- |
| `GEMINI_API_KEY` | Серверный ключ Google AI Studio |
| `GEMINI_MODEL` | Модель с structured output, по умолчанию `gemini-3.5-flash-lite`; доступность зависит от аккаунта Google |
| `SUPABASE_URL` | `https://<project-ref>.supabase.co` |
| `SUPABASE_SERVICE_ROLE_KEY` | Серверный legacy service_role key проекта; не anon/publishable key |
| `PORT` | 7860 локально; на Render используется назначенный платформой порт |
| `GRADIO_ANALYTICS_ENABLED` | `False` |

## Supabase

1. Откройте SQL Editor нужного проекта.
2. Выполните `supabase/create_applications.sql` **один раз** в новом проекте. Скрипт не перезаписывает существующую таблицу.
3. Выполните `supabase/verify_security.sql`: все семь значений должны быть `true`.
4. Возьмите URL и `service_role` key в настройках API и добавьте их в `.env` / Render Environment.

Таблица `public.applications`: `id`, `created_at`, `owner_name`, `phone`, `pet_name`, `pet_breed`, `pet_age`, `service`, `preferred_date`, `preferred_time`, `preferred_groomer`, `comment`, `status`.

RLS включён; `anon`, `authenticated` и `public` не имеют прав. Публичных политик нет. `service_role` получает только INSERT и SELECT для вставки и проверки результата. Для изменения статуса администратор использует SQL Editor. Не добавляйте публичную INSERT-политику.

## Render

Создайте **Web Service** из этого GitHub-репозитория или используйте Blueprint `render.yaml`.

- Runtime: Python
- Python: `3.12.15`
- Build Command: `pip install -r requirements.lock`
- Start Command: `python app.py`
- Health Check: `/healthz`
- Plan: Free (возможен холодный старт)
- Environment: `GEMINI_API_KEY`, `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `GEMINI_MODEL`, `GRADIO_ANALYTICS_ENABLED=False`.

Секреты внесите в **Render → Service → Environment**. `sync: false` в Blueprint требует заполнения значений при создании. Не задавайте ключи в YAML. `PORT` вручную на Render задавать не нужно. `/healthz` проверяет запуск процесса, доступ к Gemini и БД проверяется реальным сценарием ниже.

После изменения ключа нажмите **Save, rebuild, and deploy** / **Save, restart** в интерфейсе Render. После изменения кода отправьте commit: включён автоматический деплой из `main`.

## Проверка

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

Тесты покрывают: подтверждение, исправления, сохранение UUID после ошибки, отмену, изоляцию сессий, память полей, медицинский отказ, цены, отсутствие вымышленных слотов, валидацию телефона/даты/времени, безопасную обработку ошибок и серверный REST-запрос. Используют подмены API; успешные unit-тесты не доказывают работоспособность внешних ключей.

Ручной сквозной сценарий:

1. Откройте опубликованный чат, спросите цену комплекса для кошки: ожидается «от 2 500 ₽».
2. Введите: «Хочу записаться. Владелец Тестовый клиент, телефон +7 999 000 00 00. Кот Тест, метис, 3 года. Комплексный груминг для кошек. [будущая дата] в 12:00, мастер Марина. Комментарий: ТЕСТ, нет особенностей».
3. Проверьте итог, убедитесь, что до подтверждения строки в таблице нет.
4. Напишите «Подтверждаю». Сверьте номер заявки с `applications.id`, статус должен быть `new`.
5. Повторите «Подтверждаю»: строка должна остаться одна. Во второй сессии черновик должен быть пуст.
6. Проверьте RLS: запросы с anon/publishable key не должны позволять чтение и создание заявок.

## Как менять данные салона

Отредактируйте `salon.json` и отправьте commit в GitHub: Render пересоберёт приложение. Цены и тексты ответов читаются из него. При добавлении новых услуг/мастеров обновите также перечисления в `models.py`, проверки SQL отдельной миграцией и тесты. Контакты в подвале `app.py` также берутся из `salon.json`.

## Безопасность и границы

Ключи используются только сервером и не включаются в компоненты Gradio, ответы или публичные файлы. `.env` исключён из Git. Текст клиента отображается без Markdown; HTML очищается. Ошибки API скрываются от клиента, персональные данные не пишутся в логи приложения. Размер сообщения ограничен; очередь ограничена 32 запросами, последовательная обработка исключает гонки подтверждения. Это небольшой сервис с одной репликой; для большого публичного трафика нужен внешний лимит запросов.

История ограничена 80 сообщениями, контекст Gemini — последними 40. Черновик хранится отдельно; состояние сессии имеет TTL 1 час и теряется при перезапуске. Очистка чата не удаляет отправленные заявки. Сообщения передаются Google Gemini, подтверждённые заявки — в Supabase; это указано в интерфейсе. Gemini может ошибиться в извлечении полей: итог всегда проверяет клиент. Без API-ключей процесс запускается, но отвечает понятным сообщением о недоступности AI и не сообщает об успешной записи.
